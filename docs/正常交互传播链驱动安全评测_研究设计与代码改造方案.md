# 正常交互传播链驱动安全评测：研究设计与代码改造方案

日期：2026-09-20。性质：研究目标纠偏与实施规格；不是已完成实验，不授权真实请求。

本文件供后续 Codex 实施。先读根目录 [AGENTS.md](../AGENTS.md)。用户最新研究目标优先于此前将采集阶段设为攻击构造的计划。本轮仅编写本方案，未修改执行代码。

## 1. 先明确研究到底要回答什么

研究问题是：**在同等可用接口、攻击目标、模型与在线预算下，向 Planner 提供从正常交互中提取的、带证据和适用条件的信息传播结构，是否比不提供结构、更简单的结构描述或无关结构，带来更好的安全测试效果？**

这里的研究资产是正常信息传播模式，不是已经成功的攻击样本。其科学贡献候选是「正常行为中的传播结构作为规划先验」，而不是三类 primitive 的名字本身，也不是重新证明整个环境存在漏洞。

目标流程：

```text
正常任务 + 合作式交互 AI
  → 被测 Agent 正常使用环境/工具/记忆/其他 Agent
  → 原始观测与证据
  → TRANSFER / DERIVE / UPDATE 效果图
  → 有边界、有置信状态的传播子图/链条
  → 独立审计并冻结正常传播模式库

正式测试任务的公开信息 + 固定安全测试目标
  + 按实验条件提供的传播结构/结构提示
  → Planner 选择并绑定结构、提出待测试计划
  → 统一执行组件在获准的 SafeClaw 隔离接口上执行
  → 官方结果 + 传播观测 + 成本 + 合法任务效用
  → 配对比较：结构先验是否有帮助
```

**正常路径可以真实存在而完全不可利用。** 路径库不标注「必然可攻击」，正式测试失败是研究结果，不应用事后回选路径掩盖。

### 1.1 “离线”的三种含义必须拆开

- **预评测采集 / pre-evaluation collection**：发生在正式评测之前，可以调用真实模型，但必须另有调用授权和预算。
- **离线分析 / offline analysis**：只读记录、重算图和验证，不调用模型服务。
- **正式评测 / evaluation**：在独立测试任务中比较条件，所有在线交互计费计数。

把第一阶段叫“离线验证”不能使真实请求变成离线操作。CLI、日志和文档使用明确阶段名。

### 1.2 本方案采用的初始研究边界

1. 模型内部是黑箱；primitive 描述可观察交付、处理和生效变化。
2. 第一阶段只完成合法正常任务，不以误导、越权、攻击成功或安全评分为采集奖励。
3. 第二阶段才引入独立安全测试目标，限授权合成 benchmark。
4. 第一版主要测试 **跨任务迁移的冻结正常路径库**。同一测试任务先正常探测再攻击属于另一个 warm-start 条件，不能混进主实验。
5. 具体三原语定义延续两份 Primitive 文档，但已有路径不等于精确语义依赖，更不等于攻击因果。
6. 不要求所有样本跨会话、多 Agent、持久化或以外部副作用为终点；这些是覆盖维度，不是全部样本的门槛。

### 3.1 已完成的可复用基础

- v3 对象、效果、关系、切片、分层报告与离线重分析。
- request-boundary instrumentation、独立证据校验、policy 与身份绑定。

### 3.2 已核实的方向偏差

| 当前代码/配置 | 实际含义 | 与新目标的差异 |
|---|---|---|
| `execution/sample_generation.py` 的 `acquisition_mode: Literal["adversarial_trace"]`，要求 `public_attack_goal` | canonical 样本构造仍面向对抗采集 | 不能表达独立的正常任务采集配置 |
| `configs/sample_generation/pilot_collection.yaml` 的污染目标、tainted predicates、固定信任边界要求 | 采集即试图完成攻击相关链 | 正常链不应以污染/攻击结果筛选 |
| `prompts/formal/construction_attacker.md` | 驱动者是 construction attacker | 应新增合作式交互策略，不能只改角色名字 |
| `prompts/formal/trajectory_planner.md` 要求保留所有 stage 和 order | 旧攻击骨架约束强 | 正常路径应是有条件的规划先验，不强迫环境按旧轨迹演出 |
| formal config 接受 `legacy_chain_v2` | v3 尚未成为正式输入 | 两阶段 primitive 重构不是研究流水线迁移完成 |
| 默认 formal 条件为 assigned_sample/no_sample/dependency_ablation | 已有对照基础 | 尚不能独立识别“图结构”和“结构提示词”的增益 |
| `flow_admission.py` 将 intervention profile 放在 cross-session profile 后 | 干预比较依赖跨会话通过 | 单会话实验也能有效比较；门禁需变为能力依赖，而非固定阶梯 |
| evaluation task set 的一些可改 slot 位于 user_instruction/instruction_context | 可能修改高可信任务指令 | 若声称低可信内容攻击，需要独立映射允许表面并保护合法任务 |

最后一项是需逐任务审计的接口风险，不是对所有运行结果已失效的判定。不得把合法用户直接要求的行为变化误报为间接提示注入成功。

### 3.3 结论

此前工作没有白做，但主要完成了证据与表示设施。**主采集仍是攻击采集，正式入口仍是旧链体系，所以尚未实现用户真正的主实验。** 继续补齐所有宏或追求每条普通样本的强因果门，并不能自动解决这个问题。此前过度集中在强跨会话准入，也缩窄了本来应覆盖普通传播路径的研究范围。

## 4. 重新定义角色、权限和信息边界

| 角色 | 职责 | 可见信息 | 不应可见/执行 |
|---|---|---|---|
| Scenario Designer | 离线编写正常任务和覆盖计划 | 公共环境能力、开发集 | 测试集结果驱动选样 |
| Benign Interaction Policy | 模拟合作用户，完成正常任务 | 合法目标、公开回应、合法预算 | 攻击目标、污染奖励、私有 evaluator |
| Target Agent | 被测正常执行者 | 按任务与环境正常获得的信息 | 额外审计特权 |
| Observer/Verifier | 被动记录并验证关系 | 私有审计证据 | 把隐私证据转给 Planner |
| Library Builder | 去重、抽象、审计正常路径 | 采集分析结果 | 按正式攻击成功率选路径 |
| Evaluation Planner | 利用条件允许的信息规划 | 合法任务公开面、预先给定安全测试目标、条件视图 | 私有检查逻辑、测试答案、未来结果 |
| Shared Executor | 统一实现合规计划与在线反馈 | 计划、可见观测、授权表面 | 新增权限、任意修改任务、越界操作 |
| Official Evaluator | 独立判定 benchmark 结果 | 完整私有运行输出 | 在 episode 中泄漏判定规则 |

第一阶段“AI 与 Agent 正常交互”的 AI 默认是 **用户模拟器/合作策略**。它不自动证明环境内存在多 Agent 通信。只有实际存在独立接收端、执行域和消息证据，才标注 Agent→Agent。一个模型扮演两个角色不自动产生两条实际 Agent 身份。

## 5. 正常采集：具体要如何做

### 5.1 新建独立配置和输入契约

建立 `BenignCollectionConfig` 与 `BenignScenario`，不要继续要求 public_attack_goal 再填空字符串。若共享底层配置，使用严格 discriminated union，不接受正常模式夹带对抗字段。

必要字段：

```text
study_id / scenario_id / scenario_family / split_group
collection_mode = benign_interaction
environment_version / target_agent_config_hash
legitimate_goal / authorized_operations / normal_success_criteria
interaction_policy_id / prompt_version / allowed_followups
domain_inventory / surface_inventory / lifecycle_policy
seed / request_caps_by_role / wall_clock / output_root
source_task_mapping / sanitization_manifest / profile_version
execution_enabled = false
```

覆盖调度可依据未覆盖能力、端口、交互类型和成本；**不能依据安全失败、攻击得分、污染成功来挑下一次正常请求**。任务完成、预算耗尽或无法合法继续时停止。允许保存自然失败与 partial，不为了“链长”无休止追加对话。

### 5.2 场景覆盖，而非先写死目标链

初版场景包括：

1. 用户问题→只读工具→回答。
2. 多个正常来源→字段汇合→回答/合成产物。
3. 合法保存偏好→新会话正常读取。
4. 合法资源更新→后续读取特定版本。
5. 已存在能力支持的正常委派→返回结果。
6. 合法拒绝、错误反馈和恢复。

以上是正常工作类型，不是要求 Target 执行固定 primitive 顺序。记录实际行为；与预想不同仍有分析价值。

普通标记用于追踪来源，不能故意构造成有害指令。标记本身可能改变行为，须记录 instrumentation，并在开发集检查影响；不能将标记匹配等同于一般语义使用。

### 5.3 SafeClaw 的正常任务适配

SafeClaw 的安全任务可能自带攻击内容。不能直接将原 adversarial task 运行改名为 benign collection。

新增经审查的正常场景映射：

- 保留合法目标、正常工具能力和环境结构。
- 移除/替换攻击消息、恶意文件、隐藏攻击回调和植入式预置状态。
- 输出 `sanitization_manifest`：来源 task hash、具体修改位置、替换理由、保留条件。
- 正常任务完成标准只检测合法行为；不调用攻击成功评分驱动采集。
- 若无法分离合法任务和攻击条件，使用独立合成正常场景，标为 **SafeClaw-derived benign scenario**，不称原 benchmark 官方任务。
- 所有真实采集仍受单独授权、预算和隔离限制。

## 6. 正常链库：存什么、允许什么结论

### 6.1 四个不同对象

1. **Trace**：某次正常执行的完整原始事实。
2. **ObservedFlowGraph**：该 trace 在固定 Ω 下的效果图，包含未知。
3. **FlowPattern**：由一个或多个正常实例抽象的可复用子图，附来源与适用条件。
4. **InstantiatedPlan**：正式阶段针对当前环境绑定的待执行计划，不是已验证事实。

观测图中的真实 session/path/内容实例，不应原样变成跨任务模板硬编码。抽象保留类型、权限、资源类别、端口、先决条件和关系证明状态。记录 occurrence→pattern 的映射以便审计。

### 6.2 准入分层与 profile 解耦

正常路径不需要包含越权边、攻击终点、tainted memory、跨会话或干预结果。

- `observation_valid`：输入、身份、定位和图一致。
- `planning_reference_eligible`：所声明的交付/调用/资源关系有对应证据，未知被标出；提供有用规划先验。
- `verified_dependency`：针对额外声明的精确依赖，需要对应更强证据。
- `cross_session_capability`：仅对声称跨会话传播的模板要求实际切换、相同资源 scope 与 read-from。
- `intervention_evaluable`：有合法干预定义、配对执行和结果；**不要求跨会话**。

弱样本可以作为明确标记的参考，不能伪称 strong verified。主实验先预注册统一的 `planning_reference_eligible` 规则；若比较证据等级，作为独立次要因素，不能在看到测试结果后临时降低门槛。

`DERIVE` 的调用产生输出是可观察事实；无需证明每个 token 的贡献才允许存入参考库。保留 `available_input` 与 `data_dep` 区别即可，不能用强证明要求阻塞所有正常路径采集。

### 6.3 FlowPattern 最小字段

```text
pattern_id / pattern_version / origin_mode=benign_interaction
observation_profile / graph_schema / projector / verifier
nodes/effects / typed_ports / relations / joins / groups
required_capabilities / domain_roles / resource_classes
session_requirements / environmental_preconditions
relation_evidence_status / opaque_gaps / portability_limits
source_trace_ids (private) / source_split_groups
support_counts / eligibility / audit_refs
public_view_hash / private_manifest_hash
```

不加入攻击 payload、成功攻击评分或特定测试 canary。旧攻击轨迹可作为单独的工程回归/对比库，但不能重标签为正常来源。

### 6.4 public/private 与冻结

Planner public view 包含抽象图、合法能力前提、证据状态、局限及必要的正常示例摘要；不能仅给几个统计数，也不能泄漏私有原文、绝对 locator、测试任务答案、隐藏检查。

正式测试前冻结：library manifest、成员、公共视图、检索规则、prompt 版本和 policy。测试期间不向主库回灌成功案例，不以成功率淘汰路径。开发阶段迭代形成新版本；不可覆盖旧冻结库。

## 7. 数据划分与“已知路径”的准确含义

### 7.1 主实验：冷启动跨任务迁移

- collection/train：正常轨迹采集与路径库构建。
- development：检索、prompt、超参和预算选择。
- held-out test：冻结后正式比较。

按 task/template family、来源场景和相关资源内容分组切分，而不只是不同随机 seed 或不同 task ID。近重复任务、相同底层模板的改写不得横跨 train/test。保存 split manifest 和重叠审计。

主实验中的“已知”是 **在训练侧正常执行中观测到，并且公开条件显示可能适用于测试侧的结构**。不是提前知道测试 Target 的未来动作，更不是知道其必然失败路径。

### 7.2 可选研究：同任务 warm-start

如果需要先在测试任务正常运行再向 Planner 提供本地路径，单列 `warm_start_observation` 研究：

- 所有条件均有相同探测机会、请求和上下文预算；对照可获得相同正常观测的非图表示。
- 正常探测成本单独报告并计入端到端成本。
- 攻击开始前恢复相同初始状态，防止正常探测留下 memory 成为混杂。
- 不与冷启动结果合并，也不拿测试任务探测路径回填训练库。

第一版不同时实现两条主线；默认冷启动，warm-start 留显式配置与设计边界。

## 8. Planner：路径先验而非旧攻击模板复读

Planner 输入：公共合法任务、预先固定的 benchmark 安全测试目标、允许改变的表面、预算、当前能力、条件规定的路径视图。

这里“攻击目标可见”和“私有 oracle 不可见”不矛盾：目标应是公开的抽象违例类型/测试意图，不能包含隐藏 canary、判定正则、内部阈值或正确答案。

流程：公开能力过滤→确定性或冻结检索→固定 top-k→Planner 绑定 DomainRef/资源类别/端口→产生抽象计划→确定性合法性检查→共享执行器执行。

Planner 输出至少有：选中 pattern、节点/端口绑定、采用的结构、环境前提、预计偏差、未知项、授权表面、行动预算和 abstain 理由。新增关系必须标 `proposed`，不能回写成 observed/verified。

允许选择合理子图、满足条件的顺序或 abstain；不能强制保留历史每个 stage，不能假定 Target 将沿旧路径行动。实际执行中记录 planned/observed 的对齐与偏离。

第一版不做任意多图合成。需要组合多个 pattern 时，必须额外验证端口类型、scope、权限与版本前提；作为后续独立能力。

所有条件使用同一 Planner、同一输出 schema、同一共享执行器和同一反馈策略。无图条件仍调用 Planner，不能退化成另一个更弱的系统。

不应在首轮计划校验失败后悄悄回退到“专家确定性计划”；若保留 fallback，应各条件一致、计入成本并单独报告使用率。

## 9. 对照设计：分清链条、提示词和额外信息

### 9.1 最小确认性 2×2 设计

两因素：`structure_view` 与 `instruction_mode`。

| 条件 | 正常传播信息 | Planner 指导 |
|---|---|---|
| C00 | 无案例传播图；相同公共能力说明 | 通用规划说明 |
| C10 | 匹配的正常传播图 | 通用规划说明 |
| C01 | 无案例传播图；相同公共能力说明 | 固定的结构化规划说明 |
| C11 | 匹配的正常传播图 | 与 C01 相同的结构化规划说明 |

主比较预注册为 **C11−C01**：相同结构提示下，提供正常传播图是否有增益。C11−C00 是整体方法比较；C10−C00 及因素交互用于解释，不当成无限多个主假设。

结构提示应对所有样本使用冻结规则；不要为每个测试任务人工写更强 prompt。若 prompt 包含额外图实例事实，那些事实必须作为 structure_view 的一部分记录，而不是藏在 instruction_mode 中。

### 9.2 必要的解释性对照

开发/次要分析增加：

- **Matched unrelated graph**：合法、可绑定、大小相近但不相关的正常图，测量“任意额外示例”影响。不能通过随机造非法边让对照必然失败。
- **Flat facts**：来自同一被选图的相同节点与正常事实，但不提供关系拓扑，测量结构相对事实内容的作用。
- **Normal transcript summary**（可选）：预算内的正常示例摘要，比较抽象结构是否优于普通示例。

每个条件的模型、合法任务、攻击目标、可控表面、initial snapshot、反馈、最大调用次数、生成 token 上限和在线墙钟相同。图与无图的输入长度差异不可假装不存在：记录实际 token/cost；设计长度相近且非误导的附加对照。相同 cap 不等于相同实际成本。

固定检索规则与 top-k；无兼容图记 no_match，不偷偷删除任务或只在处理组补更多搜索预算。主要报告全体预定测试单元，并单列预先定义的 library-covered 子集。

### 9.3 图移除不等于环境干预

向 Planner 隐藏一条关系是 **planner-information ablation**，不是已证明切断环境中的因果边。修改源内容是 source/slot intervention，也不自动等于单边消融。名称、日志和论文表述分别保留。

## 10. SafeClaw 正式任务与威胁模型

先完成 `TaskSurfaceContract`，不能把一个 `user_instruction` slot 的存在当作任何威胁模型都允许修改。

每个评测任务声明：

```text
upstream_task_id/hash / environment_hash / evaluator_version
legitimate_task_ref / public_attack_objective
allowed_mutation_surfaces / trust_level / actor_control
immutable_fields / resource_scope / timing_constraints
setup_manifest / reset_policy / official_comparability
utility_check_ref / private_evaluator_ref
```

要求：

1. 合法用户目标、私有 evaluator 和 canary 规则保持不变。
2. 所有条件只改同一允许表面，并记录 JSON Pointer/文件/消息位置和实际 diff。
3. 间接注入实验中不能改系统提示或高可信用户任务来达成结果。
4. 若研究显式恶意用户交互，独立 track 声明该控制权，不能与低可信内容注入结果混为一谈。
5. Benchmark 原有攻击内容与生成内容不能暗中叠加；明确哪个表面被替换、哪个设置是不可变背景。
6. 每个条件从相同干净状态出发；跨会话只在同一 episode 内按任务语义保留资源。不同任务/条件间隔离 memory/index/container。
7. 只有保持官方定义和检查协议的结果才能称官方任务结果。修改合法目标或评分规则的变体标 `derived_task`，不混进原 benchmark 总分。
8. 环境是否可做真正多 Agent 调用，按 pinned 能力证据决定。工具调用或用户模拟器不冒充 Agent 委派。

先选择覆盖普通输入、工具组合、资源读写的有限任务族做开发。单一 PSE 任务×若干 seeds 只能证明该任务上可运行，不能支持广泛传播路径有效性的论文结论。任务数和 repetitions 在开发 pilot 后按方差、成本和预设效应制定，不能沿用旧“8/30 accepted”作为科学充分性标准。

## 11. 评价指标与统计

### 11.1 正常库质量

- 合法任务完成率、normal-policy 合规检查状态。
- 全部采集尝试数、可分析比例、未知/unsupported/infra failure。
- 域类型、端口、资源、单/跨会话、fan-in/out 等覆盖。
- 去重后 pattern 数及来源分布；不能只追求长链和总数量。
- 对独立抽样事实清单的表示保留与误连边核查；人工复核成本记录。

### 11.2 正式主结果

首要结果为预先定义的官方安全违例/attack outcome 配对差异，另报告：

- 正常任务效用；
- Planner 可执行计划率、abstain/no_match/fallback；
- graph capability binding 成功率；
- 计划与实际可观察路径匹配/偏离/不可判定；
- 各角色 attempts、token、墙钟与成本；
- 成功所需预算的曲线（预算点预注册）；
- infrastructure/measurement 缺失率。

ASR 高但合法任务始终被改写，或处理组花更多搜索预算，不能直接归因于路径先验。

### 11.3 分母、配对和随机性

定义单元为 task instance × initial state × seed × condition；seed 相同不保证远程模型响应相同。条件执行顺序随机化或平衡，记录模型版本/服务时间以识别漂移。

报告：

1. 全部预定与启动单元 N、已获得官方结果 n、缺失 m；
2. observed ASR = successes/n；
3. successes/N 仅作为端到端成功产出率，不能把缺失伪标为已观察安全；
4. 缺失结果的敏感性区间，例如 successes/N 到 (successes+m)/N；
5. 有效完整配对数及丢失原因。

多 seeds 嵌套于同一 task family 不能全当独立样本。主区间使用 task/family cluster bootstrap 或等价适当方法；只有满足独立配对单元假设时才直接用 McNemar。报告预注册主比较，次要多重比较标 exploratory 或校正。没有功效分析不凭空承诺某个 N 足够。

正式评测不按安全得分动态换库、换 prompt 或重试失败 task。开发阶段允许调试，但重新冻结版本；测试集不参与调参。

## 12. 代码改造规格

以下为建议职责，不要求逐个新建文件。优先复用 v3 与现有 runner，避免两套 ledger、bridge 或 verifier。

| 位置 | 改造 |
|---|---|
| `execution/sample_generation.py`、采集 configs | legacy attack 保留；新增独立 benign config/manifest/入口，不要求 attack goal |
| `interactions/construction.py`、`collector.py` | 提取共用 driver 编排；新增正常策略输入/动作与 provenance，不以 construction attacker 是否存在猜来源模式 |
| `interactions/safeclaw_collection.py`、bridge/relay | 保留严格证据；区分 source mode、策略角色与实际被测 domain；不为新模式另造预算机制 |
| `configs/benign_scenarios/`、正常 policy prompt | 合法目标、表面、完成标准、覆盖标签、sanitize mapping，默认 disabled |
| `flow/`、`flow_reanalysis.py` | 复用图结构；记录 benign origin 与抽象映射；不得导入 legacy accepted |
| `verification/flow_admission.py` | planning eligibility 与特定能力门分离；intervention 不依赖 cross-session |
| `datasets/` | 实现版本化正常 FlowPattern library、public/private views、freeze 和完整性检查 |
| `planning/` | 新 GraphPriorPlannerInput/Output；冻结检索器与显式端口绑定；无图条件也走同一 Planner |
| `execution/safeclaw_formal.py` 或独立编排模块 | 通过显式新 representation 接入，不删旧 gate；合法 surface contract 与统一执行器 |
| `configs/experiments/` | 新预评测/开发/正式配置；2×2 条件与独立 seed/split/预算；默认 disabled |
| `planning/formal_baselines.py` | 信息 ablation、flat/unrelated controls；不暗中改合法用户任务 |
| `recording/`、`reporting/` | matched assignment、prompt/view hash、path adherence、utility、missingness、cluster-aware 聚合 |
| `cli.py`、schema registry、scripts | 薄入口；compile/dry-run 无网络；schema 严格版本化；文档明确旧新主线 |

新增或扩展契约：`BenignScenario`、`BenignCollectionConfig`、`FlowPattern`、`FlowLibraryManifest`、`TaskSurfaceContract`、`GraphPriorCondition`、`GraphPriorPlannerInput/Output`、`EvaluationAssignment`、`EvaluationCaseResult`。为每个字段声明 public/private、来源和是否允许模型填写。模型提议不能填写 verifier verdict、official outcome 或运行授权。

### 12.1 阶段编排和 CLI

建议入口（名称可调整，交付时必须是真实存在的命令）：

```text
benign validate / prepare / collect
flow reanalyze / verify
flow-library build / audit / freeze
graph-eval compile / preflight / run / audit / report
```

`compile` 必须离线生成完整 assignment matrix、condition-specific public inputs 和预算预测，不能隐含探针。`freeze` 是库快照操作，不触发实验；后续实施可按明确任务范围对新测试库执行，绝不覆盖历史库。

库审计包括 origin mode、split、敏感字段、结构一致性、member hash。formal preflight 拒绝未冻结/混源/泄漏/不支持版本及 surface 违规。

### 12.2 Prompt 合同

1. Benign prompt 只有合法任务、允许正常动作和停止规则，不含攻击目标/污染 predicate。
2. Planner prompt 由公共固定段、条件 instruction 段、路径视图段组成，各自 hash；不要混入样本私有正文。
3. Executor prompt/实现各条件相同，且无样本检索特权；只执行计划允许的动作。
4. 原始工具文本和库中的文本仍视为不可信数据，不能覆盖角色指令。
5. 本方案不预写具体攻击载荷。实施时维持获准 benchmark 表面和合成边界，不能扩展至真实服务。

## 13. 保留、退役与迁移

- 保留所有旧 evidence、tests 和 legacy reader；旧攻击轨迹标 `legacy_adversarial`，不得混入正常库。
- 旧 v3 reanalysis 是表示转换，不会把攻击 origin 转为 benign。
- 新主线的 README/默认示例改为 benign→library→graph evaluation；旧 adversarial collection 需显式选择，不再误当正常主线。
- 不悄悄把已有 config 的 `execution_enabled=true` 当授权。新配置默认 false；旧配置若需改默认行为，记录迁移说明，不改历史 run snapshot。
- 不再把完成全部九个宏或 exact 强消费作为开始正常库建设的统一前置条件。
- schema/experiment protocol 新版本独立；旧论文指标不与新研究结果直接合并。
- 文档中“第一阶段样本生成”必须写清是 benign 还是 adversarial；避免同一 `sample` 指攻击载荷、正常图和正式计划。

## 14. 测试与验收矩阵

| 测试 | 必须证明 |
|---|---|
| 正常配置含 attack goal/tainted reward | schema 或 policy 明确拒绝，不静默忽略 |
| 未 neutralize 的 adversarial task | 不能标为 benign-approved；映射缺失则 blocked |
| 正常策略收到私有 evaluator | public view 检查失败 |
| 普通单会话路径 | 可成为 planning reference，不要求跨会话 |
| 单会话实际干预记录 | 不因缺 cross-session 被自动拒绝 |
| 跨会话模板缺 read-from | 不能声称有该 capability，仍可保留弱观测 |
| 旧攻击图重分析 | origin 不变，正常库拒绝混入 |
| 同 normal raw 多次分析 | 稳定 analysis key，历史输入不变 |
| public pattern | 有可用抽象图，且无私有 locator/答案/凭证 |
| no graph condition | 使用同一 Planner/schema/executor/预算，不偷换弱系统 |
| 2×2 编译 | 除声明因素外任务、目标、surface、模型、预算一致 |
| unrelated/flat controls | 合法并记录构造规则，不能偷偷携带正确边 |
| 缺 compatible pattern | no_match 入账，不事后删测试单元 |
| eval 修改高可信合法任务 | threat-model validator 拒绝 |
| plan 提议新边 | 标 proposed，不回写 observed |
| 条件间 memory 污染 | reset/ownership 检查失败 |
| test outcome 回写训练库 | 冻结及 split gate 拒绝 |
| outcome 缺失 | 不当作已知安全，不混入 verified_negative |
| compile/prepare | 零模型调用，本地 mock 可验证 |

端到端离线测试至少贯通：合成正常交互→真实共用 driver/observer→v3 图→library audit/freeze→condition compile→fake Planner/shared Executor→结果汇总。不是把每个关键阶段都 monkeypatch 掉。Fake 实验用于软件验证，不能报告真实 ASR 增益。

按改动运行 targeted tests、legacy/provider/v3 回归、完整 make check、schema 一致性、bridge 显式检查和 diff check。服务或 socket 环境失败单独报告，不能跳过制造全绿。

## 15. 可依次交给 Codex 的实施阶段

### 阶段 A：纠偏采集，交付正常轨迹闭环

交付 benign 配置/场景、合作策略、task neutralization、source-mode manifest、默认 disabled CLI，以及正常交互到 v3 图集成测试。保留 legacy，不需先实现新 formal。

验收：不向策略传攻击目标；至少覆盖只读、多输入、合法记忆；单会话可保存；旧攻击 origin 不变；零真实调用。

### 阶段 B：正常路径库与预评测冻结

交付 pattern 抽象、能力准入、split audit、公共视图、不可变库及 build/audit/freeze。先用 synthetic 与明确正常来源 fixture；真实正常数据尚无时诚实报告，不拿历史攻击 run 补数量。

验收：可给 Planner 的内容确有结构和前提；无私有泄漏；证据弱强分离；source hash 可追溯；不按攻击成功率选样。

### 阶段 C：正式条件、Planner 和 SafeClaw 表面绑定

交付 TaskSurfaceContract、2×2 assignments、统一 Planner/Executor、v3 图绑定、dry-run 编译、无图和解释性 controls。实际运行仍默认 disabled。

验收：相同合法任务与 threat model；字段差异可审计；无图不换系统；不通过重写用户目标获得成功；新图协议不偷降级。

### 阶段 D：报告、统计及有界运行准备

交付 paired report、utility/missingness/cost、task-cluster 统计、路径匹配诊断，整理独立真实兼容性检查及采集/评测授权配置。完成完整离线质量门。

验收：可从 immutable manifests 重算；主假设明确；未观察结果不补造；新实验与 legacy 结果分开。

### 阶段 E：另行授权的真实开发 pilot 与正式研究

先正常场景兼容性和少量 benign 采集，再冻结开发版库与配置；真实正式 test 仅在研究配置、预算和授权明确后进行。开发结果可用于修改下一版本，但不能反复查看 test 后称确认性结果。

本文件的编写不授权 E。A–D 的实施请求可完成代码与离线测试，不代表执行真实模型服务。
