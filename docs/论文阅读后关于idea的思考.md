# 考量

## 我们目前的思路

首先要讲清楚我们实验的思路，这也算是我们之间对齐一下，我们目前所做的事情是，使用Safeclawarena的bench，分析数据流，得到信息流图，然后看看能不能在已知信息流图的情况下，分析得到更好的攻击，然后细节上，首先是一阶段，就是通过离线的攻击分析，先得到我们的数据流图，然后，做得到数据流图的seed之后，二阶段做正式攻击，就是让planner去分析这个数据流图，看看能不能得到更好的攻击。但是分析这个过程，是基于某种原则，或者说prompt的，所以这个prompt怎么写，几乎决定了最后攻击的质量。但是怎么写，这个事情我们是没有讨论的，分析数据流是一方面，根据攻击图去攻击，则是另一方面，所以从本质上讲，我们做的工作是，怎么更好的进行攻击，那么“根据数据流进行攻击”这个过程，也非常重要，这也是我们目前实验上，非常模糊的地方。

### 数据流分析

首先是分析数据流，这个是目前思路上比较清晰的地方，我觉得整体也没什么问题，现在有很多去分析prompt怎么改变大模型的因果，记忆等内容的论文，我们可以稍微结合一下，然后获得分析数据流或者说攻击图的方案，传统攻击上也有很多这种分析攻击图的方法，这是可以类比的，区别就是传统攻击一般有污点分析或者是标记注入这种方式，但是在大模型中做不到。

如果要说这个观点有问题，那么可能的问题就是，我们的分析结果对不对了，思路本身是没有问题的。

### 攻击

然后就是攻击了。这个目前是没有任何工作的，因为我们不像AgentLAB那样，他们的侧重点是把攻击进行分类，进行的都是一些相对简单的攻击，没有那么注重攻击本身，但是我们的工作做的就是攻击，所以得到这个攻击图之后，怎么进行攻击，是一个非常需要考虑的地方。是写一个综合的prompt，对每一个数据图进行分析后攻击，还是说我可以做到更细粒读，如果做到更细粒度的话，要多么细，为什么要这么分，这个思路是否有效，包括之前我们所一直想提到的，long-horizon问题，我们怎么去做，才能实现更好的，更能清晰解释的工作，这都是需要考虑的问题，而且我觉得非常重要。如果能做到，得到更好攻击效果的分析，并且能解释清楚，我觉得肯定是可行的。
